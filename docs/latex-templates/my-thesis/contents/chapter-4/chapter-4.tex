\subsection{Implementasi Fungsi Utama}

Setiap fungsi \textit{smart contract} yang dirancang pada Subbab~3.5 telah berhasil diimplementasikan. Bagian ini menyajikan potongan kode (\textit{code snippet}) untuk tiga fungsi inti yang paling representatif dalam memetakan ketentuan UU 25/1992.

\subsubsection{Pendaftaran Anggota, registerMember}

Fungsi \texttt{registerMember()} mengimplementasikan Pasal~5(1) dan Pasal~17--18 UU 25/1992 tentang keanggotaan sukarela dan terbuka. Setiap alamat dapat mendaftar secara mandiri setelah membayar simpanan pokok melalui LakomiVault. Sistem memverifikasi pembayaran simpanan pokok, kemudian mencetak token LAK dan mencatat status keanggotaan.

\begin{lstlisting}
function registerMember() external nonReentrant {
 require(!isRegisteredMember[msg.sender], "Already registered");
 require(ILakomiVault(lakomiVault).hasPaidSimpananPokok(msg.sender),
  "Simpanan Pokok must be paid first");
 isRegisteredMember[msg.sender] = true;
 _mint(msg.sender, MEMBER_TOKENS);
 emit MemberRegistered(msg.sender);
}
\end{lstlisting}

\subsubsection{Distribusi SHU, distributeSHU}

Fungsi \texttt{distributeSHU()} mengimplementasikan Pasal~45(1--2) tentang pembagian Sisa Hasil Usaha (SHU). Pendapatan yang terakumulasi dari bunga pinjaman dialokasikan ke enam kategori sesuai basis poin yang dikonfigurasi melalui tata kelola.

\begin{lstlisting}
function distributeSHU() external onlyRole(GOVERN_ROLE) nonReentrant {
 uint256 reserve = (accumulatedRevenue * operationalReserveBps) / 10000;
 uint256 dist = accumulatedRevenue - reserve;
 uint256 cadangan = (dist * shuCadanganBps) / 10000;
 uint256 jasaModal = (dist * shuJasaModalBps) / 10000;
 uint256 jasaUsaha = (dist * shuJasaUsahaBps) / 10000;
 uint256 pendidikan = (dist * shuPendidikanBps) / 10000;
 uint256 pengurus = (dist * shuPengurusBps) / 10000;
 danaCadangan += cadangan;
 totalSHUDistributed += dist;
 accumulatedRevenue = 0;
 emit SHUDistributed(distributionId++, dist);
}
\end{lstlisting}

\subsubsection{Pemungutan Suara, castVote}

Fungsi \texttt{castVote()} mengimplementasikan Pasal~24(3) tentang prinsip satu anggota satu suara.

\begin{lstlisting}
function castVote(uint256 proposalId, Vote support) 
 external nonReentrant {
 _castVote(proposalId, support);
}

function _castVote(uint256 proposalId, Vote support) 
 internal {
 ProposalVoting storage p = proposals[proposalId];
 require(block.timestamp >= p.voteStart, "Not started");
 require(block.timestamp <= p.voteEnd, "Ended");
 require(!p.hasVoted[msg.sender], "Voted");
 p.hasVoted[msg.sender] = true;
 if (support == Vote.For) p.forVotes++;
 else if (support == Vote.Against) p.againstVotes++;
 else p.abstainVotes++;
 emit VoteCast(proposalId, msg.sender, support);
}
\end{lstlisting}

\subsubsection{Pembuatan Proposal, createProposal}

Fungsi \texttt{createProposal()} memungkinkan anggota terdaftar untuk menginisiasi proposal tata kelola. Proposal dapat bertipe SPEND (pengeluaran \textit{vault}), PARAMETER (perubahan parameter sistem), MEMBERSHIP (pencabutan/penerimaan anggota), RAT\_ANNUAL (RAT tahunan), atau CUSTOM.

\begin{lstlisting}
function createProposal(
 string calldata description,
 ProposalType _proposalType,
 address target,
 uint256 value,
 bytes calldata callData
) external nonReentrant returns (uint256) {
 require(token.isRegisteredMember(msg.sender),
  "Not registered");
 uint256 id = proposalCount++;
 Proposal storage p = proposals[id];
 p.proposer = msg.sender;
 p.description = description;
 p.proposalType = _proposalType;
 p.target = target;
 p.value = value;
 p.callData = callData;
 p.voteStart = block.timestamp;
 p.voteEnd = block.timestamp + votingPeriod;
 emit ProposalCreated(id, msg.sender);
 return id;
}
\end{lstlisting}

\subsubsection{Persetujuan dan Pencairan Pinjaman, approveLoan + disburse}

Fungsi \texttt{approveLoan()} dan \texttt{disburse()} mengimplementasikan alur persetujuan pinjaman dua tahap: APPROVER\_ROLE menyetujui permohonan, kemudian dana dicairkan dari LakomiVault ke peminjam setelah agunan dikunci.

\begin{lstlisting}
function approveLoan(uint256 loanId) 
 external onlyRole(APPROVER_ROLE) nonReentrant {
 Loan storage l = loans[loanId];
 require(l.status == LoanStatus.Pending, "Not pending");
 l.status = LoanStatus.Approved;
 emit LoanApproved(loanId, msg.sender);
}

function disburse(uint256 loanId) external nonReentrant {
 Loan storage l = loans[loanId];
 require(l.status == LoanStatus.Approved, "Not approved");
 token.lockTokens(l.borrower, l.collateralTokens);
 l.status = LoanStatus.Active;
 l.startTime = block.timestamp;
 l.dueTime = block.timestamp + defaultLoanDuration;
 emit LoanDisbursed(loanId, l.borrower, l.principal);
}
\end{lstlisting}

\subsubsection[Pembayaran Simpanan Wajib]{Pembayaran Simpanan Wajib, paySimpananWajib}

Fungsi \texttt{paySimpananWajib()} mengimplementasikan Pasal~41(2) tentang kewajiban pembayaran simpanan wajib secara berkala. Sistem melacak periode pembayaran dan memungkinkan pembayaran untuk beberapa periode sekaligus.

\begin{lstlisting}
function paySimpananWajib() external nonReentrant {
 require(simpananPokok[msg.sender] > 0, "Pokok not paid");
 stableToken.safeTransferFrom(msg.sender, address(this),
  simpananWajibAmount);
 simpananWajibTotal[msg.sender] += simpananWajibAmount;
 simpananWajibPeriodsPaid[msg.sender]++;
 simpananWajibLastPaid[msg.sender] = block.timestamp;
 contributions[msg.sender] += simpananWajibAmount;
 emit SimpananPaid(msg.sender, simpananWajibAmount, "wajib");
}
\end{lstlisting}

\subsubsection[Pemilihan Pengurus]{Pemilihan Pengurus, beginElection}

Fungsi \texttt{beginElection()} dan \texttt{finalizeElection()} mengimplementasikan Pasal~29--30. Kandidat dengan suara terbanyak memenangkan peran dengan masa jabatan 365 hari.

\begin{lstlisting}
function beginElection(bytes32 role, uint256 regPeriod, uint256 votePeriod) 
 external onlyRole(DEFAULT_ADMIN_ROLE) {
 uint256 eId = electionCount[role]++;
 elections[role][eId] = Election({
  startTime: block.timestamp,
  registrationEnd: block.timestamp + regPeriod,
  votingEnd: block.timestamp + regPeriod + votePeriod,
  finalized: false, winner: address(0), forVotes: 0
 });
 emit ElectionStarted(role, eId);
}

function finalizeElection(bytes32 role, uint256 eId)
 external onlyRole(DEFAULT_ADMIN_ROLE) {
 Election storage e = elections[role][eId];
 require(block.timestamp > e.votingEnd, "Ongoing");
 require(!e.finalized, "Done");
 address winner; uint256 maxVotes;
 for (uint i = 0; i < e.candidateList.length; i++) {
  if (e.votes[e.candidateList[i]] > maxVotes) {
   maxVotes = e.votes[e.candidateList[i]];
   winner = e.candidateList[i];
  }
 }
 e.finalized = true; e.winner = winner;
 AccessControl(target).grantRole(role, winner);
 emit ElectionFinalized(role, eId, winner);
}
\end{lstlisting}

\subsubsection[Klaim SHU Anggota]{Klaim SHU Anggota, claimSHU}

Fungsi \texttt{claimSHU()} memungkinkan anggota mengklaim bagian SHU setelah distribusi. Mencegah klaim ganda melalui \textit{mapping} \texttt{shuClaimedForDistribution}.

\begin{lstlisting}
function claimSHU(uint256 distributionId) external nonReentrant {
 require(!shuClaimedForDistribution[distributionId][msg.sender],
  "Already claimed");
 SHUDistribution storage dist = shuDistributions[distributionId];
 uint256 memberShares = vaultShares[msg.sender];
 uint256 amount = memberShares * dist.perShare;
 shuClaimedForDistribution[distributionId][msg.sender] = true;
 stableToken.safeTransfer(msg.sender, amount);
 emit SHUClaimed(distributionId, msg.sender, amount);
}
\end{lstlisting}

\section{Diskusi}

\subsection{Signifikansi Kepatuhan 100\%}

Pencapaian tingkat kepatuhan 100\% terhadap 26 ketentuan UU 25/1992 memiliki signifikansi yang melampaui sebagai angka keberhasilan pengujian. Dalam konteks \textit{regulatory technology} (RegTech), ini adalah bukti empiris pertama bahwa regulasi perkoperasian nasional dapat direpresentasikan sebagai logika komputasional yang dieksekusi secara otomatis. Jika 26 pasal UU 25/1992 dapat dikodekan, regulasi lain dengan karakteristik serupa berpotensi untuk ditransformasi dengan pendekatan yang sama, membuka ranah penelitian baru tentang \textit{computational law} di Indonesia.

Implikasi praktisnya juga signifikan. Audit kepatuhan konvensional memerlukan pemeriksaan manual ribuan transaksi oleh auditor eksternal dengan biaya tinggi. Dalam sistem Lakomi, verifikasi terjadi secara otomatis pada setiap transaksi: \texttt{onlyRole} memastikan otorisasi, \texttt{nonReentrant} mencegah serangan, dan logika bisnis yang dikodekan menegakkan aturan tanpa kemungkinan penyimpangan. Peralihan dari \textit{ex-post audit} ke \textit{ex-ante enforcement} ini merepresentasikan perubahan paradigma, dari "percaya lalu verifikasi" menjadi "verifikasi adalah bawaan sistem."

\subsection{Kelayakan dari Perspektif Gas}

Berdasarkan pengukuran pada DChain mainnet dengan harga gas 0,000000002 DKT/gas (2 nano-DKT), seluruh operasi koperasi memiliki biaya minimal, operasi termahal (\texttt{requestLoan} pada 245.599 gas) hanya memerlukan kurang dari 0,0005 DKT. Satu siklus pinjaman penuh (\texttt{requestLoan} + \texttt{approveLoan} + \texttt{disburse} + \texttt{repayInFull}) mengonsumsi sekitar 620.000 gas, atau sekitar 0,001 DKT. Biaya ini hampir dapat diabaikan untuk operasional koperasi harian, memvalidasi bahwa DChain sebagai blockchain konsorsium menawarkan kelayakan ekonomi yang baik untuk aplikasi koperasi. Sebagai perbandingan, biaya administrasi koperasi konvensional, mencakup gaji staf, pencetakan dokumen, dan audit eksternal, diperkirakan mencapai 5--15\% dari pendapatan tahunan, jauh melampaui biaya gas sistem on-chain.

\subsection{Keterbatasan dan Validitas Eksternal}

Penelitian ini tidak bertujuan menghasilkan produk yang siap diadopsi oleh koperasi riil, melainkan merancang dan memverifikasi artefak \textit{proof-of-concept} yang membuktikan kelayakan pendekatan pemetaan regulasi-ke-kode. Dalam kerangka DSR, evaluasi artefak tidak mensyaratkan deployment produksi, Hevner \cite{hevner2004design} mengakui bahwa evaluasi dapat dilakukan melalui metode analitis (verifikasi kepatuhan), eksperimental (analisis gas), dan komparatif (perbandingan sistem), yang ketiganya telah dilaksanakan dalam penelitian ini. Ketiga metode evaluasi tersebut mendemonstrasikan \textit{utility} artefak, fungsionalitas yang benar (26/26 skenario lulus), kelayakan ekonomi (biaya gas minimal), dan posisi unik terhadap sistem pembanding, tanpa memerlukan organisasi koperasi riil sebagai subjek pengujian.

Empat \textit{smart contract} Lakomi merupakan implementasi langsung dari 26 ketentuan UU 25/1992 yang telah diverifikasi kata demi kata terhadap teks hukum autentik. Validitas pemetaan tidak bergantung pada apakah koperasi riil menggunakan sistem ini, melainkan pada apakah logika yang dikodekan sesuai dengan bunyi pasal. Setiap pasal diterjemahkan menjadi kondisi persyaratan, aksi, kendala, dan aktor berwenang yang dapat diverifikasi melalui pengujian fungsional berbasis Hardhat. Dengan demikian, kontribusi utama penelitian ini adalah bukti empiris bahwa regulasi perkoperasian nasional dapat direpresentasikan sebagai logika komputasional yang \textit{self-executing}, bukan hanya argumen konseptual.

Validitas eksternal memang terbatas pada konteks DChain, dan hasil tidak dapat digeneralisasi ke platform lain tanpa validasi ulang. Pengujian skala laboratorium dengan jumlah anggota dan transaksi terbatas belum mencerminkan kondisi produksi dengan ribuan anggota dan puluhan ribu transaksi per tahun. Antarmuka prototipe belum diuji dengan pengguna koperasi sesungguhnya, penerimaan pengguna, kemudahan penggunaan, dan dampak terhadap partisipasi merupakan dimensi evaluasi yang penting namun belum tercakup. Validasi pada DChain \textit{mainnet} dengan partisipan koperasi riil, \textit{stress testing}, dan evaluasi pengalaman pengguna merupakan langkah esensial untuk mengonfirmasi temuan-temuan awal ini, sebagaimana diidentifikasi pada Batasan Penelitian (Subbab 1.4) dan Saran (Subbab 5.3).

\section{Validasi Formula}

Tiga formula utama dalam sistem Lakomi, bunga pinjaman, kuorum tata kelola, dan distribusi SHU, divalidasi melalui perhitungan manual yang dibandingkan dengan hasil eksekusi \textit{smart contract}.

\subsection{Validasi Formula Bunga Pinjaman}

Bunga pinjaman dihitung menggunakan formula bunga sederhana (Persamaan~\ref{eq:bunga}). Contoh perhitungan untuk pinjaman 1.000 IDRX selama 90 hari:

\begin{equation}
\text{Bunga} = \frac{1.000 \times 5\% \times 90}{365} = \frac{1.000 \times 0,05 \times 90}{365} = \frac{4.500}{365} \approx 12,33 \text{ IDRX}
\end{equation}

Total pengembalian yang harus dibayarkan peminjam adalah $1.000 + 12,33 = 1.012,33$ IDRX. Hasil eksekusi \texttt{calculateInterest(1000, 90)} pada \textit{smart contract} mengembalikan nilai yang sama (12,33 IDRX dengan presisi 6 desimal), mengonfirmasi bahwa implementasi on-chain sesuai dengan spesifikasi formula.

\subsection{Validasi Formula Kuorum}

Kuorum tata kelola dihitung sebagai $\lceil \text{memberCount} \times 67\% \rceil$. Contoh perhitungan untuk koperasi dengan 10 anggota:

\begin{equation}
\text{Quorum} = \lceil 10 \times 0,67 \rceil = \lceil 6,7 \rceil = 7 \text{ suara}
\end{equation}

Pembulatan ke atas (\textit{ceiling}) memastikan bahwa kuorum tidak dapat dicapai oleh kurang dari dua per tiga anggota. Dengan 10 anggota, diperlukan minimal 7 suara agar proposal dinyatakan lolos. Pengujian pada \textit{smart contract} mengonfirmasi bahwa proposal dengan 6 suara ditolak (\texttt{quorumNotMet}) dan proposal dengan 7 suara dinyatakan lolos, dengan syarat $\text{forVotes} > \text{againstVotes}$.

\subsection{Validasi Formula Distribusi SHU}

Distribusi SHU dihitung berdasarkan basis poin (\textit{basis points}) yang dialokasikan ke enam kategori (Persamaan~\ref{eq:shu-split}). Contoh perhitungan untuk total pendapatan 1.000 IDRX:

\begin{align}
\text{Cadangan Operasional} &= 1.000 \times 10\% = 100 \text{ IDRX} \nonumber \\
\text{SHU}_{\text{distributable}} &= 1.000 - 100 = 900 \text{ IDRX} \nonumber \\
\text{Dana Cadangan} &= 900 \times 5\% = 45 \text{ IDRX} \nonumber \\
\text{Jasa Modal} &= 900 \times 40\% = 360 \text{ IDRX} \nonumber \\
\text{Jasa Usaha} &= 900 \times 40\% = 360 \text{ IDRX} \nonumber \\
\text{Dana Pendidikan} &= 900 \times 5\% = 45 \text{ IDRX} \nonumber \\
\text{Dana Pengurus} &= 900 \times 5\% = 45 \text{ IDRX} \nonumber \\
\text{Dana Kesejahteraan Sosial} &= 900 \times 5\% = 45 \text{ IDRX} \nonumber
\end{align}

Total alokasi: $45 + 360 + 360 + 45 + 45 + 45 = 900$ IDRX, yang sama dengan $\text{SHU}_{\text{distributable}}$. Eksekusi \texttt{distributeSHU()} pada \textit{smart contract} menghasilkan alokasi yang identik, mengonfirmasi bahwa perhitungan on-chain sesuai dengan ketentuan Pasal 45(2) UU 25/1992.

Alokasi Jasa Modal dan Jasa Usaha masing-masing sebesar 40\% mencerminkan kontribusi ganda anggota, sebagai penyetor modal melalui simpanan dan sebagai pengguna jasa koperasi melalui pinjaman, sesuai dengan prinsip keanggotaan ganda (\textit{dual identity}) yang dianut UU 25/1992. Kedua komponen ini didistribusikan secara pro-rata berdasarkan \textit{shares} masing-masing anggota, memastikan bahwa anggota yang berkontribusi lebih besar menerima bagian SHU yang proporsional.
